CPU가 여러 명령어를 동시에 처리하기 위해 각 명령어를 여러 단계로 분할하고, 각 단계를 다른 명령어와 겹쳐서 실행하는 기법입니다.

## 동작 방식

전통적인 CPU는 한 번에 하나의 명령어만 처리하지만, 파이프라이닝을 적용한 CPU는 명령어 인출(IF), 해독(ID), 실행(EX), 메모리 접근(MEM), 결과 저장(WB) 등 여러 단계로 나누어 각기 다른 명령어를 동시에 처리합니다.

```
시간 →
명령어1: IF ID EX MEM WB
명령어2:    IF ID EX MEM WB
명령어3:       IF ID EX MEM WB
```

## 파이프라인 위험(Pipeline Hazard)

파이프라이닝은 성능 향상을 가져오지만, 특정 상황에서는 오히려 성능 저하를 유발하는 파이프라인 위험이 발생할 수 있습니다.

- **데이터 위험(Data Hazard)**: 데이터 의존적인 두 명령어를 동시에 실행할 때 발생합니다. 명령어 B가 명령어 A의 연산 결과에 의존한다면, A의 결과 저장 단계가 끝나야 B가 이를 사용할 수 있습니다.
- **제어 위험(Control Hazard)**: 분기(branch)나 조건문으로 인해 다음에 실행할 명령어가 결정되지 않아 파이프라인이 멈추는 경우입니다. 분기 예측 기법으로 완화하지만, 예측 실패 시 계산된 파이프라인을 모두 버려야 해 성능 저하가 발생합니다.
- **구조적 위험(Structural Hazard)**: 서로 다른 명령어가 ALU, 레지스터 같은 동일한 CPU 자원을 동시에 사용하려 할 때, 한쪽이 멈추면서 발생합니다.

## 핵심 정리

명령어 파이프라이닝은 명령어 실행 단계를 겹쳐 처리량을 높이는 기법이지만, 데이터·제어·구조적 위험으로 인해 이론적인 성능 향상을 온전히 달성하지 못할 수 있습니다.
