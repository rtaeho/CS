[[스레드]] 내에서 실행되며 운영체제 개입 없이 사용자 공간(user space)에서 협력적으로 스케줄링되는 경량 실행 단위입니다.

## 스레드와의 차이

- **메모리 사용량**: 스레드는 생성 시 커널에 의해 고정된 스택 메모리(JVM 기본 약 1MB)를 할당받지만, 코루틴은 자체 스택 없이 실행 상태만 저장하므로 몇 KB 수준의 메모리만 사용합니다.
- **[[컨텍스트 스위칭]] 비용**: 스레드 전환은 운영체제가 개입해 레지스터, 메모리 맵 등의 상태를 저장·복원해야 하지만, 코루틴 전환은 커널 개입 없이 사용자 공간에서 실행 지점과 로컬 변수만 저장하면 되어 비용이 훨씬 낮습니다.
- **생성 및 관리 비용**: 스레드 생성은 시스템 콜을 통해 커널 리소스를 할당받아야 하지만, 코루틴 생성은 단순한 객체 할당과 유사해 비용이 작습니다.
- **일시 중단 메커니즘**: 스레드는 블로킹 작업(I/O 등) 중 완전히 멈춰 다른 작업을 수행할 수 없지만, 코루틴은 일시 중단 지점에서 실행을 멈추고 사용 중이던 스레드를 반납해 다른 코루틴이 그 스레드를 이어서 쓸 수 있게 합니다.

## 가벼운 이유

코루틴은 스레드라는 OS 자원을 직접 점유하지 않고, 소수의 스레드 위에서 다수의 코루틴을 사용자 공간 스케줄링으로 실행합니다. 스레드가 블로킹되는 지점에서도 코루틴은 스레드를 점유한 채 대기하는 대신 실행을 중단하고 스레드를 반납하므로, 수천 개의 코루틴도 적은 수의 스레드만으로 효율적으로 처리할 수 있습니다.

## 코드 예시 - Kotlin

```kotlin
// 스레드 1000개 생성 시 약 1GB의 메모리 필요, 각 스레드는 sleep 동안 블로킹됨
for (i in 1..1000) {
    Thread {
        Thread.sleep(1000)
    }.start()
}

// 코루틴 1000개를 생성해도 몇 MB 수준의 메모리만 사용
runBlocking {
    for (i in 1..1000) {
        launch {
            delay(1000) // 코루틴만 일시 중단되고, 스레드는 다른 코루틴이 사용
        }
    }
}
```

## 핵심 정리

코루틴이 스레드보다 가벼운 이유는 자체 스택 대신 최소한의 상태만 저장해 메모리를 적게 쓰고, 전환 시 OS 개입 없이 사용자 공간에서 컨텍스트 스위칭이 일어나며, 생성 비용이 낮고, 블로킹 대신 일시 중단으로 스레드를 반납해 소수의 스레드로도 대량의 [[동시성]] 작업을 처리할 수 있기 때문입니다.
