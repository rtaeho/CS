간선을 가중치 순으로 정렬해 사이클을 만들지 않는 간선만 차례로 골라 최소 신장 트리(MST)를 만드는 그리디 알고리즘입니다.

## 동작 과정

```
[ 그래프 ] (괄호는 가중치)
   1 ——(1)—— 2
   |  \      |
(3)|   \(4)  |(2)
   |    \    |
   3 ——(5)—— 4

간선 목록을 가중치 오름차순 정렬:
(1-2, 1), (2-4, 2), (1-3, 3), (1-4, 4), (3-4, 5)

유니온 파인드 초기: {1} {2} {3} {4}

(1-2, 1): find(1)≠find(2) → 채택   MST={1-2}, 집합 {1,2} {3} {4}
(2-4, 2): find(2)≠find(4) → 채택   MST={1-2, 2-4}, 집합 {1,2,4} {3}
(1-3, 3): find(1)≠find(3) → 채택   MST={1-2, 2-4, 1-3}, 집합 {1,2,3,4}
                                   간선 3개 = V-1 → 종료
(1-4, 4): (검사하면) find(1)=find(4) → 사이클, 버림
(3-4, 5): 이미 종료

MST 총 가중치 = 1 + 2 + 3 = 6

[ 결과 ]
   1 ——(1)—— 2
   |          |
(3)|          |(2)
   3          4
```

가장 싼 간선부터 고르되 사이클만 피하면 전체 최소가 된다는 것이 그리디 성립 근거입니다.

## 구현

```java
// edges: int[]{from, to, weight}
int kruskal(int n, List<int[]> edges) {
    edges.sort((a, b) -> a[2] - b[2]);   // 가중치 오름차순

    UnionFind uf = new UnionFind(n);
    int total = 0, picked = 0;

    for (int[] e : edges) {
        if (uf.union(e[0], e[1])) {      // 사이클이 아니면 채택
            total += e[2];
            if (++picked == n - 1) break;  // 간선 V-1개면 MST 완성
        }
    }
    return picked == n - 1 ? total : -1;   // -1 = 그래프가 연결되지 않음
}
```

사이클 판별을 [[유니온 파인드]]에 맡기는 것이 핵심입니다. `union`이 `false`를 반환하면 두 노드가 이미 같은 집합, 즉 그 간선은 사이클을 만듭니다.

## 복잡도

| 구분 | 복잡도 | 근거 |
|---|---|---|
| 시간 | O(E log E) | 간선 [[정렬]]이 지배적. 이후 union-find는 간선당 거의 O(1) |
| 공간 | O(V + E) | 간선 목록 + parent 배열 |

E ≤ V²이므로 `log E`와 `log V`는 상수배 차이입니다.

## 주의사항

- **종료 조건**: 간선을 V−1개 채택하면 MST가 완성되므로 즉시 끝낼 수 있다. 끝까지 돌아도 틀리진 않지만 불필요하다
- **연결 그래프가 아닐 때**: V−1개를 못 채우면 MST가 존재하지 않는다(최소 신장 **숲**이 된다). 위 구현처럼 개수를 세어 구분한다
- **정렬 비교자 오버플로**: 가중치가 매우 크면 `a[2] - b[2]`가 오버플로 난다. `Integer.compare(a[2], b[2])`가 안전하다 — [[Comparator]] 참고
- **[[프림]]과의 선택**: 간선이 적은 희소 그래프는 크루스칼, 간선이 많은 밀집 그래프는 프림이 유리하다

## 핵심 정리

- 간선을 가중치 오름차순으로 보며 사이클이 안 생기는 것만 채택
- 사이클 판별은 [[유니온 파인드]]로 — `union` 실패 = 사이클
- 시간복잡도 O(E log E), 정렬이 지배적
- 간선 V−1개를 채택하면 MST 완성, 못 채우면 비연결 그래프
