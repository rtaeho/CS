한 노드에서 시작해 현재 트리에 붙은 간선 중 가장 싼 것을 하나씩 흡수하며 최소 신장 트리를 키워가는 그리디 알고리즘입니다.

## 동작 과정

```
[ 그래프 ] (괄호는 가중치)
   1 ——(1)—— 2
   |  \      |
(3)|   \(4)  |(2)
   |    \    |
   3 ——(5)—— 4

시작=1, MST={}, 방문={1}
우선순위 큐에 1의 간선 투입: (1,1-2), (3,1-3), (4,1-4)

PQ=[(1,2), (3,3), (4,4)]        ← (가중치, 도착노드)
  (1,2) 꺼냄 → 2 미방문 → 채택
    MST={1-2}, 방문={1,2}, 2의 간선 추가: (2,4)
PQ=[(2,4), (3,3), (4,4)]
  (2,4) 꺼냄 → 4 미방문 → 채택
    MST={1-2, 2-4}, 방문={1,2,4}, 4의 간선 추가: (5,3)
PQ=[(3,3), (4,4), (5,3)]
  (3,3) 꺼냄 → 3 미방문 → 채택
    MST={1-2, 2-4, 1-3}, 방문={1,2,3,4}  ← 전체 방문, 종료
  (4,4) 꺼냄 → 4 이미 방문 → 버림
  (5,3) 꺼냄 → 3 이미 방문 → 버림

MST 총 가중치 = 1 + 2 + 3 = 6
```

[[크루스칼]]과 결과는 같지만 자라는 방식이 다릅니다. 크루스칼은 **간선을 전부 정렬해두고 전역에서** 고르고, 프림은 **현재 트리에 인접한 간선 중에서만** 고릅니다.

## 구현

```java
// graph: 인접 리스트, int[]{다음 노드, 가중치}
int prim(int start, List<List<int[]>> graph) {
    int n = graph.size();
    boolean[] visited = new boolean[n];
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[1] - b[1]); // {노드, 가중치}

    pq.offer(new int[]{start, 0});
    int total = 0, count = 0;

    while (!pq.isEmpty() && count < n) {
        int[] cur = pq.poll();
        int node = cur[0], weight = cur[1];

        if (visited[node]) continue;   // 이미 트리에 흡수된 노드
        visited[node] = true;
        total += weight;
        count++;

        for (int[] edge : graph.get(node)) {
            if (!visited[edge[0]]) {
                pq.offer(new int[]{edge[0], edge[1]});
            }
        }
    }
    return count == n ? total : -1;   // -1 = 그래프가 연결되지 않음
}
```

구조가 [[다익스트라]]와 거의 같습니다. 차이는 큐에 넣는 값이 **시작점까지의 누적 거리**(다익스트라)인지 **그 간선 하나의 가중치**(프림)인지입니다.

## 복잡도

| 구현 방식 | 시간 | 근거 |
|---|---|---|
| 우선순위 큐 + 인접 리스트 | O(E log V) | 간선마다 큐 삽입 O(log V) |
| 인접 행렬 + 선형 탐색 | O(V²) | 매 단계 최소 간선을 V개 중 선형 탐색 |

공간복잡도는 O(V + E). 간선이 V²에 가까운 밀집 그래프에서는 O(V²) 구현이 오히려 빠릅니다.

## 주의사항

- **방문 체크 시점**: 큐에서 꺼낼 때 확인해야 한다. 넣을 때만 걸러내면 같은 노드가 서로 다른 가중치로 여러 번 들어와 더 싼 간선을 놓칠 수 있다
- **누적 거리와 혼동**: 다익스트라처럼 `dist[node] + weight`를 큐에 넣으면 MST가 아니라 최단 경로 트리가 된다. 프림은 간선 가중치 그 자체를 넣는다
- **비연결 그래프**: 방문한 노드 수가 V에 못 미치면 MST가 없다
- **[[크루스칼]]과의 선택**: 희소 그래프(E ≈ V)는 크루스칼, 밀집 그래프(E ≈ V²)는 프림이 유리하다

## 핵심 정리

- 한 노드에서 시작해 인접 간선 중 최소를 흡수하며 트리를 키운다
- [[PriorityQueue]] 사용 시 O(E log V), 밀집 그래프는 O(V²) 구현이 유리
- 구조는 [[다익스트라]]와 같고, 큐에 넣는 값만 다르다(누적 거리 vs 간선 가중치)
- 방문 체크는 큐에서 꺼낼 때
