무게 제한이 있는 배낭에 각 물건을 **통째로 넣거나 넣지 않는** 선택만으로 가치의 합을 최대화하는 조합 최적화 문제입니다.

## 동작 과정

물건 3개 `(무게, 가치)` = `(1,1)`, `(3,4)`, `(4,5)`, 배낭 용량 `5`로 추적합니다.
`dp[i][w]`는 **앞에서 i개 물건만으로 용량 w를 넘지 않게 담을 수 있는 최대 가치**입니다.

```
초기값: dp[0][w] = 0 (물건이 없으면 가치 0)

물건1 (무게1, 가치1) 반영
dp[1][w] = max(dp[0][w], dp[0][w-1] + 1)   (w >= 1)

  w     0  1  2  3  4  5
dp[1]   0  1  1  1  1  1

물건2 (무게3, 가치4) 반영
dp[2][w] = max(dp[1][w], dp[1][w-3] + 4)   (w >= 3)

  w     0  1  2  3  4  5
dp[2]   0  1  1  4  5  5
                 ↑  ↑
         dp[1][0]+4=4   dp[1][1]+4=5

물건3 (무게4, 가치5) 반영
dp[3][w] = max(dp[2][w], dp[2][w-4] + 5)   (w >= 4)

  w     0  1  2  3  4  5
dp[3]   0  1  1  4  5  6
                       ↑
               dp[2][1]+5=6  ← dp[2][5]=5보다 큼

정답 = dp[3][5] = 6
→ 물건1(무게1,가치1) + 물건3(무게4,가치5) = 무게5, 가치6
  (물건2 하나만 담은 가치4보다 큼)
```

각 칸 `dp[i][w]`는 i번째 물건을 **담지 않는 경우**(`dp[i-1][w]`)와 **담는 경우**(`dp[i-1][w - weight[i]] + value[i]`) 중 큰 값을 선택합니다. 물건을 쪼갤 수 없으므로 담는 경우는 전체 무게를 그대로 빼야 하고, 이 때문에 각 물건을 단 한 번만 선택지로 반영해야 합니다.

## 구현

```java
int knapsack(int[] weight, int[] value, int capacity) {
    int n = weight.length;
    int[][] dp = new int[n + 1][capacity + 1];

    for (int i = 1; i <= n; i++) {
        for (int w = 0; w <= capacity; w++) {
            dp[i][w] = dp[i - 1][w];
            if (w >= weight[i - 1]) {
                dp[i][w] = Math.max(dp[i][w], dp[i - 1][w - weight[i - 1]] + value[i - 1]);
            }
        }
    }

    return dp[n][capacity];
}

// 공간 최적화: 1차원 배열 + 용량을 뒤에서부터 순회
int knapsackOptimized(int[] weight, int[] value, int capacity) {
    int n = weight.length;
    int[] dp = new int[capacity + 1];

    for (int i = 0; i < n; i++) {
        for (int w = capacity; w >= weight[i]; w--) {
            dp[w] = Math.max(dp[w], dp[w - weight[i]] + value[i]);
        }
    }

    return dp[capacity];
}
```

## 복잡도

| 구분 | 복잡도 | 근거 |
|---|---|---|
| 시간 | O(n × W) | 물건 n개 × 용량 w개 칸을 한 번씩 채움 |
| 공간 (2차원) | O(n × W) | 물건별 선택 여부를 담은 전체 테이블 유지 |
| 공간 (1차원 최적화) | O(W) | 이전 물건까지의 결과만 한 줄로 유지 |

n, W 모두 커지면 테이블 크기가 급격히 늘어나므로([[동적 계획법]]의 중복 부분 문제를 캐싱해 지수 시간 완전 탐색을 다항 시간으로 줄인 것), 가치가 정수가 아니거나 용량이 매우 크면(가짜 다항 시간, pseudo-polynomial) 이 접근이 비효율적일 수 있습니다.

## 주의사항

- **1차원 최적화 시 순회 방향이 핵심**: 용량을 `capacity`에서 `weight[i]`까지 **내림차순**으로 순회해야 한다. 오름차순으로 순회하면 같은 물건을 그 반복 안에서 여러 번 담는 결과가 되어 **무한 배낭 문제(unbounded knapsack)**가 되어버린다.
- **0-1 배낭은 물건을 쪼갤 수 없다**. 무게 대비 가치 비율로 그리디하게 담으면(분수 배낭 문제) 최적해를 보장하지 못하므로 DP가 필요하다.
- 물건 개수 n과 용량 W 모두가 매개변수인 **2차원 문제**라는 점에서, 1차원 DP(피보나치 등)보다 테이블 설계를 명확히 해야 한다.

## 핵심 정리

- 각 물건을 **담는다 / 담지 않는다** 두 선택 중 더 나은 결과를 선택하는 DP
- 상태: `dp[i][w]` = i번째 물건까지 고려했을 때 용량 w에서의 최대 가치
- 점화식: `dp[i][w] = max(dp[i-1][w], dp[i-1][w-weight[i]] + value[i])`
- 시간/공간 O(n × W), 1차원 배열 + 용량 내림차순 순회로 공간을 O(W)까지 줄일 수 있다
