큰 문제를 작은 부분 문제로 나누고, 그 결과를 저장해 재사용함으로써 중복 계산을 없애는 알고리즘 설계 기법입니다.

## 동작 과정

피보나치수열로 **메모이제이션(top-down)**과 **타뷸레이션(bottom-up)**의 차이를 비교합니다.

```
메모이제이션 (재귀 + 캐시, 필요한 것만 계산)

fib(5)
├─ fib(4)
│  ├─ fib(3)
│  │  ├─ fib(2)
│  │  │  ├─ fib(1) = 1
│  │  │  └─ fib(0) = 0
│  │  │  memo[2] = 1
│  │  └─ fib(1) = 1          ← memo 적중, 재귀 없이 반환
│  │  memo[3] = 2
│  └─ fib(2)                 ← memo 적중, 재귀 없이 반환
│  memo[4] = 3
└─ fib(3)                    ← memo 적중, 재귀 없이 반환
memo[5] = 5

타뷸레이션 (반복문 + 배열, 작은 문제부터 전부 계산)

dp[0] = 0
dp[1] = 1
dp[2] = dp[1] + dp[0] = 1
dp[3] = dp[2] + dp[1] = 2
dp[4] = dp[3] + dp[2] = 3
dp[5] = dp[4] + dp[3] = 5
```

캐시 없이 재귀만 하면 `fib(3)`, `fib(2)` 같은 하위 문제가 호출 경로마다 중복 계산되어 O(2ⁿ)이 됩니다. [[메모이제이션]]은 그 중복을 없애기 위해 계산 결과를 저장해두고 재사용합니다.

## 구현

```java
// 메모이제이션 (top-down)
int[] memo;

int fibMemo(int n) {
    memo = new int[n + 1];
    Arrays.fill(memo, -1);
    return fib(n);
}

private int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    memo[n] = fib(n - 1) + fib(n - 2);
    return memo[n];
}

// 타뷸레이션 (bottom-up)
int fibTab(int n) {
    if (n <= 1) return n;
    int[] dp = new int[n + 1];
    dp[1] = 1;
    for (int i = 2; i <= n; i++) {
        dp[i] = dp[i - 1] + dp[i - 2];
    }
    return dp[n];
}
```

## 복잡도

| 방식 | 시간 | 공간 | 근거 |
|---|---|---|---|
| 캐시 없는 순수 재귀 | O(2ⁿ) | O(n) | 같은 하위 문제가 호출 경로마다 중복 계산됨 |
| 메모이제이션 | O(n) | O(n) | 하위 문제 n개를 각각 한 번만 계산, 캐시 배열 O(n) |
| 타뷸레이션 | O(n) | O(n) | 하위 문제 n개를 순서대로 한 번씩 계산 |

타뷸레이션은 `dp[i]`가 바로 앞 두 값에만 의존하므로 변수 두 개로 O(1) 공간까지 줄일 수 있습니다(공간 최적화, rolling variable).

## 주의사항

- **적용 조건**: 최적 부분 구조(부분 문제의 최적해로 전체 최적해를 구성할 수 있음)와 중복 부분 문제(같은 하위 문제가 반복 등장함) 두 조건을 모두 만족해야 DP가 의미 있다. 둘 중 하나라도 없으면 캐시가 효과가 없거나 틀린 답이 나온다
- **메모이제이션의 재귀 깊이**: n이 커지면 재귀 호출 스택이 깊어져 `StackOverflowError`가 날 수 있다. 타뷸레이션은 반복문이라 이 문제가 없다
- **타뷸레이션의 전이 순서**: 작은 문제부터 큰 문제로 채우려면 `dp[i]`가 어떤 `dp[j]`(j < i)에 의존하는지, 즉 전이 방향이 명확해야 한다. 방향이 복잡하면(사이클이 있거나 순서가 불분명하면) 타뷸레이션 대신 메모이제이션이 더 쉽다
- **메모이제이션은 필요한 하위 문제만** 계산하고, 타뷸레이션은 **테이블 전체를 순서대로** 계산한다. 입력에 따라 일부 하위 문제만 필요하다면 메모이제이션이 더 적은 계산을 한다

## 핵심 정리

- DP는 **최적 부분 구조 + 중복 부분 문제**가 있는 문제에 적용한다
- **메모이제이션(top-down)**: 재귀 + 캐시, 필요한 하위 문제만 계산, 스택 오버플로 위험
- **타뷸레이션(bottom-up)**: 반복문 + 배열, 작은 문제부터 전부 계산, 재귀 없음
- 둘 다 시간복잡도는 같고(O(n)), 선택은 구현 편의성과 재귀 깊이 제약에 따라 달라진다
