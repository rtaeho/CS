큰 수를 다룰 때 오버플로를 피하기 위해 모든 중간 결과를 특정 수로 나눈 나머지로만 유지하는 연산 방식입니다.

## 동작 과정

```
예시 1: 곱셈의 분배법칙으로 오버플로 피하기
MOD = 1_000_000_007
a = 123456789, b = 987654321

직접 계산: a * b = 121932631112635269  (long 범위는 안 넘지만, 항이 누적되면 쉽게 넘친다)

안전한 방식: 매 연산마다 바로 mod를 취한다
  (a * b) % MOD
= ((a % MOD) * (b % MOD)) % MOD
= (123456789 * 987654321) % MOD
= 121932631112635269 % MOD
= 652839556

예시 2: 음수 나머지 정규화
Java의 %는 피연산자의 부호를 따른다 → (-7) % 5 = -2 (수학적 나머지 3과 다름)
정규화: ((-7 % 5) + 5) % 5 = (-2 + 5) % 5 = 3

예시 3: 나눗셈은 분배되지 않는다 → 모듈러 역원을 곱한다
MOD = 7 (소수), a = 3, b = 2  →  (a / b) % MOD 를 구하고 싶다

페르마의 소정리: MOD가 소수면  b^(MOD-2) % MOD  가 b의 모듈러 역원
  inverse(2) = 2^(7-2) % 7 = 2^5 % 7 = 32 % 7 = 4   (2 * 4 = 8 ≡ 1 mod 7 확인)

  (a / b) % MOD = (a * inverse(b)) % MOD = (3 * 4) % 7 = 12 % 7 = 5
```

곱셈의 분배법칙 `(a * b) % m = ((a % m) * (b % m)) % m`은 나머지 연산 자체의 정의에서 바로 유도됩니다. `a = q1*m + r1`, `b = q2*m + r2`로 쓰면 `a*b`를 `m`으로 나눈 나머지는 결국 `r1*r2`를 `m`으로 나눈 나머지와 같기 때문입니다. 덧셈도 같은 원리로 분배되지만, **나눗셈은 분배되지 않으므로** 나누는 수의 모듈러 역원을 곱하는 방식으로 대체해야 합니다.

## 구현

```java
static final long MOD = 1_000_000_007L;

// 음수가 들어와도 항상 [0, m) 범위로 정규화
static long mod(long a, long m) {
    return ((a % m) + m) % m;
}

static long addMod(long a, long b, long m) {
    return mod(a, m) + mod(b, m) >= m
            ? mod(a, m) + mod(b, m) - m
            : mod(a, m) + mod(b, m);
}

static long mulMod(long a, long b, long m) {
    return mod(a, m) * mod(b, m) % m;
}

// 거듭제곱 중간값도 매 단계 mod를 취해 오버플로를 막는다 ([[분할정복 거듭제곱]]과 동일한 분할정복 구조)
static long modPow(long base, long exp, long m) {
    if (exp == 0) {
        return 1L % m;
    }
    long half = modPow(base, exp / 2, m);
    long result = mulMod(half, half, m);
    if (exp % 2 != 0) {
        result = mulMod(result, mod(base, m), m);
    }
    return result;
}

// m이 소수일 때만 성립하는 페르마의 소정리 기반 모듈러 역원
static long modInverse(long a, long primeMod) {
    return modPow(a, primeMod - 2, primeMod);
}
```

## 복잡도

- `mod`, `addMod`, `mulMod`: O(1)
- `modPow`, `modInverse`: O(log exp) — 지수를 절반씩 줄여가는 분할정복 구조라 [[분할정복 거듭제곱]]과 동일한 호출 횟수를 가진다

## 주의사항

- **페르마의 소정리는 법(modulus)이 소수일 때만 성립한다.** 소수가 아닌 법에 대한 모듈러 역원은 [[유클리드 호제법]]을 확장한 확장 유클리드 호제법으로 구해야 하며, 그마저도 `a`와 법이 서로소(gcd = 1)일 때만 역원이 존재한다
- **나눗셈은 분배되지 않는다**: `(a / b) % m`을 `(a % m) / (b % m)`으로 계산하면 틀린다. 반드시 `b`의 모듈러 역원을 곱하는 형태로 바꿔야 한다
- **중간 곱셈값 오버플로**: `mod(a, m) * mod(b, m)`은 `m`이 10^9 근처여도 곱한 결과가 10^18 근처까지 커질 수 있다. `long` 범위(약 9.2 * 10^18) 안에 들어오는지 항상 확인하고, 법이 더 크면 `Math.multiplyHigh`나 `BigInteger`, 또는 Barrett/Montgomery 축약을 고려한다
- Java의 `%`는 피연산자의 부호를 그대로 따르므로, 음수가 섞일 수 있는 입력은 `mod(a, m)`처럼 `+ m` 정규화를 거쳐야 한다

## 핵심 정리

- 덧셈·곱셈은 분배된다: `(a op b) % m = ((a % m) op (b % m)) % m`
- 나눗셈은 분배되지 않는다 — 나누는 수의 모듈러 역원을 곱해야 한다
- 음수는 `((a % m) + m) % m`으로 정규화한다
- 모듈러 역원은 법이 소수면 페르마의 소정리(`a^(m-2) % m`)로, 아니면 확장 유클리드 호제법으로 구한다
- 경쟁 프로그래밍에서 큰 수의 오버플로를 피하는 기본 도구이며, [[분할정복 거듭제곱]]의 모듈러 거듭제곱 형태로 가장 자주 함께 쓰인다
