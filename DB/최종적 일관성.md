분산 시스템에서 고가용성을 유지하기 위해 사용하는 일관성 모델로, 데이터가 수정되면 변경 내용이 비동기적으로 다른 노드에 전파되어 일시적으로는 노드 간 데이터가 다를 수 있지만 시간이 지나면 모든 노드가 결국 동일한 데이터를 갖게 되는 것을 의미합니다.

## 동작 방식

```
① 클라이언트가 노드 A에 데이터 수정 요청
② 노드 A는 즉시 응답 (복제를 기다리지 않음)
③ 변경 내용이 비동기로 노드 B, C에 전파
④ 전파가 완료되기 전까지 노드 B, C는 오래된 데이터를 반환할 수 있음
⑤ 시간이 지나 전파가 끝나면 모든 노드가 동일한 데이터를 가짐
```

복제를 수행 중인 노드에도 조회 연산을 허용하여 높은 가용성을 유지할 수 있지만, 그 대가로 일시적인 데이터 불일치가 발생해 클라이언트가 오래된 데이터를 읽을 수 있다는 단점이 있습니다.

## 강한 일관성과의 차이

**강한 일관성(Strong Consistency)** 은 특정 연산이 끝난 직후 모든 노드가 동일한 데이터를 갖도록 보장하는 모델입니다. 데이터를 수정한 직후 다른 노드에서 읽더라도 반드시 최신 값을 얻을 수 있지만, 복제가 완료될 때까지 다른 노드의 읽기 연산을 차단해야 하므로 그만큼 가용성이 희생됩니다.

|구분|최종적 일관성|강한 일관성|
|---|---|---|
|복제 방식|비동기|동기(또는 복제 완료까지 대기)|
|가용성|높음|상대적으로 낮음|
|데이터 최신성|일시적으로 오래된 값 가능|항상 최신 값 보장|
|대표 사례|DNS, 쇼핑몰 재고, Cassandra, DynamoDB|금융/결제 시스템|

두 모델의 관계는 [[CAP]] 이론의 AP(가용성+분단 내성)와 CP(일관성+분단 내성) 선택과도 맞닿아 있습니다. AP를 선택한 시스템이 타협점으로 택하는 것이 최종적 일관성입니다.

## 핵심 정리

최종적 일관성은 **가용성을 우선하고 일관성을 일시적으로 양보**하는 모델로, 모든 노드가 즉시 같은 데이터를 가질 필요는 없지만 결국에는 동일해진다는 것을 보장합니다. 반대로 강한 일관성은 항상 최신 데이터를 보장하는 대신 가용성을 희생합니다.
