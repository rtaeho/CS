외부 라이브러리의 예상치 못한 버그나 비정상 동작으로 기능에 문제가 생겼을 때, 원인을 좁히고 영향도를 분석한 뒤 상황에 맞는 대응 전략을 선택하는 문제 해결 절차입니다.

## 대응 절차

1. **원인 파악**: 라이브러리 버전 변경 이력, 특정 컴포넌트에서만 재현되는지 등을 확인해 문제 범위를 좁힙니다. Git 히스토리와 GitHub 이슈를 참고해 실제로 라이브러리의 버그인지, 잘못된 사용 방식 때문인지 구분합니다.
2. **영향도 분석과 임시 대응**: 문제가 사용자에게 미치는 영향을 파악하고 우회 방법을 검토합니다. 예를 들어 레이아웃이 깨지면 스타일만 덮어쓰거나, 기능이 아예 동작하지 않으면 대체 라이브러리를 쓰거나 해당 부분을 직접 구현합니다.
3. **이해관계자 공유**: 해결에 시간이 걸릴 것으로 판단되면 기획자, PO, QA 등에게 상황과 예상 영향, 대응 계획을 공유해 일정 차질을 예방합니다. 동료 개발자와도 이슈를 공유해 더 나은 해결책을 함께 찾을 수 있습니다.
4. **장기적인 해결**: 라이브러리에 버그 리포트를 제출하거나 PR로 직접 기여합니다. 긴급한 경우에는 라이브러리를 포크해 수정한 뒤 사용하되, 추후 되돌릴 수 있도록 변경 사항을 문서화해 둡니다.

## 핵심 정리

라이브러리 자체를 탓하기보다 원인을 명확히 좁히고, 배포 일정에 맞는 임시 우회책을 마련한 다음, 이해관계자와 상황을 공유하며 장기적으로는 업스트림에 기여하는 방식으로 대응하는 것이 중요합니다.
