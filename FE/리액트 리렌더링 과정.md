state나 props 변경으로 시작해 화면 갱신까지 이어지는 리액트의 렌더링 처리 흐름이며, Trigger → Render → Commit 세 단계로 나뉩니다.

## 단계별 동작

- **Trigger**: 컴포넌트의 state나 props가 변경되면 리액트가 리렌더링이 필요하다고 판단하고 업데이트를 큐에 등록합니다.
- **Render**: 변경된 상태를 반영한 새 [[Virtual DOM]] 트리를 생성하고, 이전 트리와 비교(Diffing)해 변경 지점을 계산합니다. 이 단계에서는 실제 DOM에 아무 변화도 일어나지 않습니다.
- **Commit**: Render 단계에서 계산된 변경 사항만 실제 DOM에 반영합니다. 변경되지 않은 요소는 그대로 유지되며, 이 시점에 화면이 실제로 갱신됩니다.

## 리렌더링 횟수 최적화

- 한 이벤트 핸들러 안에서 여러 번 상태를 변경해도 [[배칭 업데이트]]에 의해 하나의 리렌더링으로 묶여 처리됩니다.
- React 18부터는 `Promise`, `setTimeout`, 네이티브 이벤트 핸들러 등에서도 자동 배칭이 적용됩니다.

```jsx
function App() {
  const [a, setA] = useState(0);
  const [b, setB] = useState(0);

  const handleClick = () => {
    setA(a + 1);
    setB(b + 1); // 배칭으로 리렌더링 1회
  };

  return <button onClick={handleClick}>Click</button>;
}
```

## 핵심 정리

리액트는 상태 변경(Trigger) → 가상 DOM 계산(Render) → 실제 DOM 반영(Commit) 순서로 화면을 갱신하며, 여러 상태 변경은 배칭을 통해 한 번의 리렌더링으로 최적화됩니다.
