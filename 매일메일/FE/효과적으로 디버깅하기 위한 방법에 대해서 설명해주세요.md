효과적인 [[디버깅]]을 위해서는 먼저 문제를 정확히 이해하고, 재현 가능한 형태로 작게 분리하는 것이 중요합니다.

## 오류 메시지와 증상 확인

가장 먼저 오류 메시지, 스택 트레이스, 발생 조건을 꼼꼼히 확인합니다. 어떤 입력, 브라우저, API 응답, 사용자 행동에서 문제가 발생하는지 구체적으로 파악해야 합니다.

## 문제 격리

코드베이스가 클수록 여러 요소가 얽혀 있을 가능성이 큽니다. 이때는 문제를 작게 분리해 재현 가능한 환경을 만들어야 합니다.

- 문제가 발생한 컴포넌트만 따로 실행합니다.
- 간단한 테스트 데이터를 사용합니다.
- 최근 변경된 코드부터 확인합니다.
- 네트워크, 상태, 렌더링, 스타일 문제를 분리해서 봅니다.

## 정상 흐름과 문제 흐름 비교

정상적으로 동작할 때 애플리케이션이 어떤 순서로 실행되어야 하는지 먼저 그려봅니다. 이후 문제 상황의 실제 흐름과 비교하면 차이가 생기는 지점을 찾기 쉽습니다.

## 도구 활용

브라우저 개발자 도구, IDE 디버거, React DevTools, 네트워크 탭, 로그, 테스트 코드를 적극적으로 활용합니다. 원인을 찾은 뒤에는 공식 문서, GitHub Issue, 신뢰할 수 있는 자료를 확인해 해결 방법을 검증합니다.

## 정리

디버깅은 원인을 추측해서 바로 고치는 일이 아니라, 문제를 재현하고 범위를 좁히며 가설을 검증하는 과정입니다. 해결 후에는 같은 문제가 다시 발생하지 않도록 테스트나 기록을 남기는 것이 좋습니다.
