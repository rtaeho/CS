생성자를 여러 차례 호출해도 실제로 생성되는 객체를 하나로 유지하는 디자인 패턴입니다.

## 핵심 특징

- 객체가 최초로 생성된 이후에는 생성자나 객체 생성 메서드가 기존에 만들어진 객체를 반환합니다.
- 생성자를 `private`으로 제한해 외부에서 임의로 인스턴스를 생성하지 못하게 막습니다.
- 정적 필드나 정적 메서드를 통해 유일한 인스턴스에 접근합니다.

## Java 예시

```java
public class Singleton {

  private static final Singleton INSTANCE = new Singleton();

  // 생성자 호출 제한
  private Singleton() { ... }

  public static Singleton getInstance() {
    return INSTANCE;
  }
}
```

## 장점

- 하나의 객체를 여러 상황에서 재사용할 수 있어 메모리 낭비를 방지할 수 있습니다.
- 여러 다른 객체가 하나의 인스턴스에 쉽게 접근할 수 있어 편리합니다.

## 주의사항

- 전역 객체를 생성한다는 특성상 코드의 복잡도를 높이고, 테스트하기 어려운 코드를 만들 수 있습니다.
- 싱글턴 객체를 지연 초기화(lazy initialization)하고 싶을 때 여러 [[스레드]]가 동시에 생성자에 접근하면 두 개 이상의 객체가 생성될 수 있으므로 동시성 문제를 고려해야 합니다.
- 테스트에서는 이전 테스트가 수정한 싱글턴 객체의 상태를 초기화하는 과정이 필요합니다.
- 싱글턴 객체가 인터페이스를 구현하지 않은 경우, 테스트 환경에서 가짜 구현체로 대체하여 주입하기 어렵습니다.

## 핵심 정리

싱글턴 패턴은 애플리케이션 전역에서 하나의 인스턴스만 유지하도록 강제하는 패턴입니다. 메모리 낭비를 막고 공유 접근을 편리하게 하지만, 동시성 문제와 테스트 격리 문제를 함께 고려해야 합니다.
