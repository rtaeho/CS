전송할 메시지를 패킷이라는 작은 단위로 나눠 보내고, 각 패킷이 그때그때 최적 경로를 찾아 이동한 뒤 목적지에서 다시 조립되는 방식입니다.

## 동작 과정

1. **분할** — 메시지를 일정 크기의 패킷으로 나눕니다.
2. **헤더 부착** — 각 패킷에 출발지·목적지 주소, 순서 번호 등을 담은 헤더를 붙입니다.
3. **전달** — 라우터가 각 패킷의 목적지를 보고 그 시점의 최적 경로로 넘깁니다. 패킷마다 경로가 달라질 수 있습니다.
4. **재조립** — 목적지에서 순서 번호를 보고 원래 메시지로 복원합니다.

인터넷이 이 방식으로 동작합니다.

## 특징

- **전송하는 동안에만 네트워크 자원을 사용**하므로 여러 통신이 같은 회선을 나눠 쓸 수 있어 회선 이용 효율이 높습니다.
- 경로가 수시로 변경될 수 있어, 일부 구간에 장애가 생겨도 우회 경로로 전달됩니다.
- 대신 경로 탐색 과정에서 지연이 발생할 수 있습니다.
- 패킷마다 헤더가 붙으므로 그만큼 오버헤드가 생깁니다.
- 패킷이 서로 다른 경로로 오면 도착 순서가 뒤바뀌거나 유실될 수 있어, 순서 보장과 재전송은 상위 계층(예: [[TCP]])이 담당합니다.

## 회선 교환과의 비교

| | [[회선 교환]] | 패킷 교환 |
| --- | --- | --- |
| 경로 | 통신 전 미리 고정 | 패킷마다 달라질 수 있음 |
| 자원 점유 | 통신 내내 독점 | 전송하는 순간만 사용 |
| 회선 효율 | 낮음 | 높음 |
| 오버헤드 | 없음 | 패킷 헤더만큼 발생 |
| 사례 | 유선 전화망 | 인터넷 |

## 핵심 정리

- 메시지를 패킷으로 쪼개 보내고 목적지에서 재조립하는 방식입니다.
- 전송 순간에만 자원을 쓰므로 회선 효율이 높고 장애에 강합니다.
- 대신 경로 탐색 지연과 헤더 오버헤드가 있고, 순서·유실 보장은 상위 계층의 몫입니다.
