세션이 끝나도 남아 다음 세션에서 다시 읽을 수 있게 저장하는, 경험에서 얻은 지식이다.
기준 시점: 2026-11

## 왜 필요한가

컨텍스트 윈도우는 유한하고, 세션이 끝나면 프롬프트에 없던 내용은 사라진다. 매 세션마다 같은 실수를 반복하거나 같은 설명을 다시 들어야 한다면 에이전트는 경험에서 아무것도 배우지 못하는 셈이다. 에이전트 메모리는 이 문제를 모델 가중치를 바꾸는 파인튜닝이나 한 대화 안에서만 통하는 in-context learning과는 다른 방식으로 푼다 — 세션 밖에 결과를 써 두고, 다음 세션이 시작할 때 다시 읽어들이는 방식이다.

## 작업 메모리와 장기 메모리

[[CoALA]]는 메모리를 작업 메모리(working memory)와 장기 메모리로 나눈다. 작업 메모리는 지금 컨텍스트 윈도우 안에 있어서 LLM이 바로 볼 수 있는 것이고, 장기 메모리는 컨텍스트 밖, 즉 세션이 끝나도 남는 외부 저장소다. 에이전트 메모리가 다루는 질문은 이 둘 사이에서 **무엇을 언제 옮기느냐**다.

MemGPT(Packer et al., 2023)는 이 경계를 운영체제의 가상 메모리 페이징에 비유해 설명한다. 메인 컨텍스트(모델이 보는 프롬프트)와 외부 컨텍스트(디스크에 해당하는 저장소)로 나누고, 모델이 함수 호출로 정보를 그 사이에서 옮기거나 자신의 컨텍스트를 직접 편집하게 만든다. 컨텍스트 윈도우를 고정된 크기의 메모리로, 장기 메모리를 그보다 훨씬 큰 저장 공간으로 보고 그 사이를 관리하는 시스템을 설계하는 틀이다.

## 무엇을 저장할지

Anthropic은 메모리를 "미래에 무엇이 필요할지에 대한 예측"이라고 표현한다. 규칙 하나를 적어두는 것은 그 규칙이 나중에 다시 쓸모 있을 것이라는 예측이라는 뜻이다. 그래서 저장할 가치가 있는 것은 당장의 중간 계산이 아니라, 다음에도 참이거나 다시 참고할 만한 것들이다.

- 반복해서 필요한 사실 — 설정값, 사용자 선호, 환경의 제약
- 실패에서 검증된 규칙이나 전략 — 같은 실수를 다시 하지 않도록 고친 내용
- 진행 중인 작업의 체크포인트 — 다음 세션이 이어갈 수 있는 상태

반대로 한 세션 안에서만 의미 있는 중간 계산이나 탐색 과정은 장기 메모리로 승격시킬 이유가 없다. Anthropic은 저장 형태가 올라갈수록(검색 가능한 이벤트 로그 → 메모리 노트 → 위키 같은 메모리 표현 → 매 세션 시작 시 주입되는 컨텍스트) 토큰 비용이 커진다고 설명하며, 그래서 주입 단계는 작게 유지해야 한다고 말한다.

## 언제 저장하고 언제 불러올지

쓰는 시점은 두 갈래다.

- **세션 중 즉시 쓰기**: 작업하면서 중요한 결정이나 실패를 바로 노트에 남긴다. 당장 반영되지만, 노트를 쓰는 동안 작업에 쓸 주의력(컨텍스트 예산)을 깎아 먹는다.
- **오프라인 정리**: 세션이 끝난 뒤 로그를 다시 검토해 노트의 오류를 고치고 더 압축된 표현을 만든다. 비용을 세션 밖으로 미루지만 결과가 바로 보이지 않는다.

불러오는 시점도 둘로 나뉜다. 매 세션 시작 시 작업 메모리로 주입하는 방식과, 필요할 때 [[RAG]]처럼 검색으로 장기 메모리에서 꺼내오는 방식이다. 전부를 매번 주입하면 토큰 예산을 금방 다 쓰므로, 자주 쓰는 소수만 주입하고 나머지는 검색에 맡기는 조합이 실제로 많이 쓰인다 — [[컨텍스트 엔지니어링]]의 사전 검색·즉시 검색 구분과 같은 문제다.

## 주의사항

- 메모리 사용법을 세세히 지시하면 오히려 성능이 떨어질 수 있다. Anthropic이 Claude에게 포켓몬 레드를 플레이시킨 평가에서 "실패만 기록하라"는 규칙을 주자 점수가 떨어졌고, 목적만 알려주고 무엇을 기록할지는 모델 판단에 맡겼을 때 더 잘 작동했다.
- 작업 메모리만으로 설계하면 컨텍스트 윈도우가 찰수록 오래된 정보가 밀려난다. 장기 메모리로 옮기는 경로가 없으면 [[컨텍스트 압축]]만으로는 세션을 넘어가는 지식을 지킬 수 없다.
- 오프라인에서 로그를 다시 검토해 메모리 노트의 오류를 고치고 표현을 다듬는 과정을 Anthropic은 [[드리밍]]이라 부른다.

## 핵심 정리

- 에이전트 메모리는 세션을 넘어 남기는, 외부에 쓰고 다시 읽는 지식이며 가중치 변화나 세션 안 in-context learning과는 다르다
- [[CoALA]]의 작업 메모리(컨텍스트 윈도우 안) vs 장기 메모리(컨텍스트 밖) 구분이 기본 틀이고, MemGPT는 이를 OS의 가상 메모리 페이징에 비유해 함수 호출로 옮기는 시스템을 제안했다
- 저장할지 말지는 "미래에 다시 쓸모 있을 예측"인지로 판단하고, 저장 형태가 올라갈수록(로그 → 노트 → 표현 → 주입) 토큰 비용이 커지므로 주입 단계는 작게 유지한다
- 쓰기는 세션 중 즉시 쓰기와 오프라인 정리로, 불러오기는 주입과 검색으로 나뉘며 실제로는 이 둘을 섞어 쓴다
