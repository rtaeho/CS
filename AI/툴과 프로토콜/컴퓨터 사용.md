에이전트가 화면을 스크린샷으로 보고 마우스·키보드 입력을 내보내 GUI를 직접 조작하게 하는 클라이언트 툴입니다.
기준 시점: 2026-11

## 왜 필요한가

API가 있는 서비스는 [[함수 호출]]이나 [[MCP]]로 바로 붙일 수 있지만, 사람만 쓰도록 만들어진 레거시 데스크톱 앱이나 전용 API가 없는 웹사이트는 그런 통합 지점이 없다. 컴퓨터 사용은 에이전트가 사람이 보는 화면을 그대로 보고 사람이 쓰는 입력 장치를 그대로 흉내 내게 해서, 통합 API가 없는 GUI까지 조작 대상으로 넓힌다.

## 동작 과정

Claude 공식 문서에 따르면 현재 버전은 `computer_toolset_20260801`이고, `screenshot`·`zoom`·클릭류·`scroll`·`type`·`key` 등 17개의 "멤버 툴"로 구성된 하나의 toolset이다. 각 멤버는 `tool_use` 블록의 `toolset_name: "computer"`와 멤버 이름(`name`)으로 식별되며, 모델은 실제 화면 픽셀을 보는 게 아니라 애플리케이션이 찍어 보낸 스크린샷 이미지만 받는다.

```
1. 요청 전송 — toolset 선언 + 사용자 프롬프트
2. 모델 응답 — stop_reason: "tool_use", computer tool_use 블록 1개 이상
   (한 턴에 클릭→입력→스크린샷처럼 여러 액션을 계획할 수 있다)
3. 애플리케이션이 VM/컨테이너에서 각 액션을 순서대로 실행
4. tool_use_id로 매칭된 tool_result 반환
   (screenshot·zoom은 이미지, 나머지는 짧은 텍스트)
5. 모델이 더 이상 computer 호출을 반환하지 않을 때까지 반복
```

모델이 보내는 좌표는 **애플리케이션이 돌려준 스크린샷의 픽셀 좌표계**(원점은 좌상단)다. 모델은 실제 화면 크기를 모르므로, 스크린샷을 리사이즈해서 보냈다면 애플리케이션이 좌표를 실제 화면 크기로 다시 환산해야 한다.

한 턴에 여러 액션을 배치로 반환할 수 있는데, 공식 문서는 반드시 순서대로 실행하고, 하나가 실패하면 그 뒤 블록에는 모두 `is_error: true`를 "Not executed: an earlier computer action in this turn failed."라는 고정 문구로 돌려주라고 명시한다.

## 트레이드오프

- API가 없는 GUI까지 조작 대상으로 넓힐 수 있지만, 그 대가로 스크린샷마다 토큰(문서 기준 이미지 1장당 대략 1,000~1,800 입력 토큰)을 쓰고 액션-응답 왕복마다 지연이 생긴다.
- 모델이 화면을 "본다"지만 실제 해상도를 모르기 때문에, 애플리케이션이 스크린샷을 리스케일했다면 좌표 환산을 직접 책임져야 한다. 이 환산을 빠뜨리면 클릭이 엉뚱한 곳을 때린다.
- 공식 문서는 요청당 스크린샷이 20장을 넘으면 이미지별로 더 엄격한 제한이 걸린다고 밝히며, 매 턴 정리하지 말고 배치로 정리하라고 권한다.

## 주의사항

공식 문서가 직접 꼽는 보안 권고:

- 전용 VM·컨테이너에서, 최소 권한으로 돌린다
- 계정 로그인 같은 민감한 정보를 모델에 주지 않는다
- 인터넷 접근을 허용 도메인 목록으로 제한한다
- 결제·약관 동의처럼 되돌릴 수 없는 행동 앞에서는 사람의 확인을 거친다
- 사용자에게 위험을 알리고 동의를 받은 뒤에만 제품에 켠다

문서는 웹페이지나 이미지에 심어진 지시(프롬프트 인젝션)를 모델이 따를 수 있다고도 명시하며, 스크린샷을 포함한 툴 결과를 검사하는 분류기를 함께 쓴다고 밝힌다. 레퍼런스 구현은 Xvfb 가상 디스플레이 위에 Docker 컨테이너를 올려 돌린다고 설명한다.

## 핵심 정리

- 컴퓨터 사용은 모델이 화면을 스크린샷으로만 보고, `screenshot`·클릭·`type`·`scroll` 등 멤버 툴로 마우스·키보드를 흉내 내는 클라이언트 툴이다
- 모델은 실제 기기에 직접 붙지 않는다 — 모든 액션은 애플리케이션이 통제하는 VM·컨테이너 안에서 실행된다
- 좌표는 애플리케이션이 돌려준 스크린샷의 픽셀 좌표계이므로, 리스케일했다면 애플리케이션이 직접 환산해야 한다
- API가 없는 GUI까지 조작 범위를 넓히는 대신, 스크린샷 토큰 비용·지연·프롬프트 인젝션 같은 새 위험을 떠안는다
