언어 에이전트를 메모리·행동 공간·의사결정 절차 세 축으로 나눠 서술하는 개념 틀이며, 서로 다른 에이전트 구현을 같은 어휘로 비교할 수 있게 해줍니다.
기준 시점: 2026-10

## 왜 필요한가

에이전트 논문과 프레임워크는 각자 자기 용어를 씁니다. 같은 자리를 어떤 쪽은 "스크래치패드", 어떤 쪽은 "상태", 어떤 쪽은 "메모리"라 부릅니다. 그래서 두 구현을 나란히 놓아도 무엇이 실제로 다른지 집어내기 어렵습니다.

CoALA(Cognitive Architectures for Language Agents)는 인지과학과 기호주의 AI의 인지 아키텍처 전통을 빌려, LLM을 쓰는 에이전트를 **모듈형 메모리 / 구조화된 행동 공간 / 일반화된 의사결정 절차**로 나눠 설명합니다. 새 기법을 제안하는 게 아니라 기존 기법들을 같은 좌표계에 올려놓고 읽는 틀입니다. 2023년 9월 arXiv 공개(2309.02427), TMLR 게재.

## 메모리

메모리를 작업 메모리와 장기 메모리로 나누고, 장기 메모리를 다시 셋으로 가릅니다.

- **작업 메모리(working memory)** — "LLM 호출 사이에 유지되는 자료구조". 지금 의사결정 주기의 입력, 활성화된 지식, 목표를 담고 나머지 구성요소를 잇는 중심이다
- **에피소드 메모리(episodic)** — 지난 의사결정 주기의 경험
- **의미 메모리(semantic)** — 세계와 에이전트 자신에 대한 지식
- **절차 메모리(procedural)** — 두 형태가 있다. LLM 가중치에 암묵적으로 들어 있는 것과, 에이전트 코드에 명시적으로 적힌 것. 설계자가 초기화해야 한다

프롬프트에 매번 실려 들어가는 것(작업 메모리)과 외부 저장소에서 꺼내오는 것(장기 메모리)을 구분해두면, 컨텍스트 설계 논의가 "무엇을 어느 층에 둘지"로 정리됩니다.

## 행동 공간

행동을 환경을 건드리는 **외부 행동**과 메모리를 다루는 **내부 행동**으로 가릅니다.

```
                ┌─ 외부(grounding) ─ 물리 환경
                │                    사람·다른 에이전트와의 대화
                │                    디지털 환경
  행동 공간 ────┤
                │              ┌─ 검색(retrieval) : 장기 메모리 → 작업 메모리 읽기
                └─ 내부 ───────┼─ 추론(reasoning) : 작업 메모리 읽고 쓰기 (LLM 호출)
                               └─ 학습(learning)  : 장기 메모리에 쓰기
```

내부 행동 셋은 메모리를 어느 방향으로 건드리는지로 갈립니다. 검색은 장기 메모리에서 작업 메모리로 읽어오고, 추론은 작업 메모리를 읽고 써서 갱신하며, 학습은 장기 메모리에 씁니다.

## 의사결정 절차

에이전트는 의사결정 주기를 반복합니다. 논문은 이 주기를 프로그램의 `main` 절차에 비유합니다. 한 주기는 두 단계입니다.

1. **계획 단계(planning)** — 추론과 검색 행동으로 무엇을 할지 정한다. 세 하위 단계로 나뉜다
   - **제안(proposal)**: 후보 행동을 하나 이상 생성한다
   - **평가(evaluation)**: 각 후보에 값을 매긴다
   - **선택(selection)**: 실행할 행동을 고르거나, 후보를 모두 버리고 제안으로 되돌아간다
2. **실행 단계(execution)** — 고른 행동을 실제로 수행한다. 이때 수행되는 행동은 외부 grounding 행동이거나 학습 행동이다. 환경에서 온 관찰이 다음 주기의 입력이 된다

계획 단계는 LLM 호출과 메모리 조회로만 돌고 환경을 건드리지 않습니다. 환경에 영향을 주는 것은 실행 단계뿐이라는 분리가, 되돌릴 수 없는 행동 앞에 승인 절차를 끼워 넣을 자리를 만들어줍니다.

## 이 틀로 기존 패턴 읽기

- [[ReAct]]: 추론(내부)과 grounding(외부)을 번갈아 내보내는 구성. 학습 행동이 없어 주기를 넘어 남는 것이 없다
- [[에이전트 리플렉션]]: 자기비평을 에피소드 메모리에 쓰는 **학습 행동**을 더한 것으로 읽힌다
- [[플래닝]]의 plan-and-execute: 계획 단계의 제안·평가·선택을 미리 길게 뽑아두고 실행을 뒤로 미룬 형태
- 검색으로 외부 문서를 끌어와 컨텍스트를 채우는 구성은 의미 메모리에 대한 검색 행동에 해당한다

이렇게 놓고 보면 "이 에이전트에 무엇이 없는가"를 묻기 쉬워집니다. 장기 메모리 중 어느 층이 비었는지, 학습 행동이 아예 없는지, 계획 단계에 평가가 있는지가 바로 점검 항목이 됩니다.

## 핵심 정리

- 새 기법이 아니라 에이전트를 비교할 **공통 어휘**를 주는 틀
- 메모리 = 작업 메모리 + 장기 메모리(에피소드·의미·절차)
- 행동 = 외부 grounding + 내부(검색·추론·학습)
- 의사결정 = 계획(제안 → 평가 → 선택)과 실행의 반복, 환경을 건드리는 것은 실행 단계뿐
- 활용법은 내 에이전트에서 비어 있는 칸을 찾는 점검 목록으로 쓰는 것
