긴 탐색이나 반복 작업을 별도의 컨텍스트 창을 가진 서브에이전트에 맡기고, 그 결과를 요약만 돌려받아 상위 컨텍스트를 깨끗하게 유지하는 방법이다.
기준 시점: 2026-11

## 왜 필요한가

에이전트가 코드를 찾아 읽고, 테스트를 돌려 로그를 받고, 여러 후보를 검색해 비교하는 과정은 대화 기록에 그대로 쌓이면 금방 [[컨텍스트 압축]]이 필요할 정도로 불어난다. 탐색 과정 자체는 결론을 내리는 데만 쓰이고 그 뒤로는 거의 다시 참조되지 않는데도, 압축하지 않으면 그 분량이 남은 작업 내내 컨텍스트를 차지한다. 서브에이전트에 탐색을 떠넘기면 그 과정 전체가 메인 대화 바깥의 별도 창에서 일어나고, 메인 대화에는 결론만 돌아온다.

## 구조

Claude Code 문서는 서브에이전트가 "자신만의 컨텍스트 창에서, 별도의 시스템 프롬프트와 특정 툴 접근 권한, 독립된 권한으로" 동작한다고 설명한다. 메인 대화의 기록·이미 읽은 파일·이미 호출한 스킬을 보지 못한 채 완전히 새로 시작하며, 메인 에이전트가 작성한 위임 메시지(작업 설명)만 받아서 작업한다. 작업을 마치면 "자신의 컨텍스트 안에서 그 작업을 하고 요약만 반환한다" — 테스트 로그나 검색 결과처럼 분량이 큰 중간 결과물은 서브에이전트의 창 안에 남고 메인 대화로 넘어오지 않는다.

```
메인 대화 컨텍스트                              서브에이전트 컨텍스트 (새로 시작)
┌─────────────────────────┐                  ┌──────────────────────────┐
│ 대화 기록 전체            │   위임 메시지      │ 대화 기록 없음              │
│ 이미 읽은 파일들           │ ───────────────▶ │ 작업 설명만 받고 시작        │
│ 이미 호출한 스킬들         │                  │ 허용된 툴로 반복 호출        │
└─────────────────────────┘                  │ 로그·검색 결과 등이 여기 쌓임 │
          ▲                                   └────────────┬─────────────┘
          │                요약만 반환                        │
          └───────────────────────────────────────────────┘
```

예외는 포크(fork)로, "처음부터 시작하는 대신 부모 대화를 물려받는다." 포크는 컨텍스트를 격리하지 않고 공유하는 쪽을 택한 변형이다.

서브에이전트는 포그라운드와 백그라운드로 나뉜다. 포그라운드는 결과를 곧바로 돌려주고, 백그라운드는 "나중 턴의 완료 알림"으로 결과를 전달하며 메인 에이전트는 그 알림이 올 때까지 기다렸다가 보고한다. 또한 백그라운드 서브에이전트는 기본적으로 더 작은 내장 툴 집합만 받는다.

## 트레이드오프

- **격리가 공짜가 아니다**: 문서는 "서브에이전트도 자신의 요청을 보내고, 이는 메인 대화와 같은 사용량 한도에 포함된다"고 밝힌다. 컨텍스트를 아끼는 대신 별도의 모델 호출 비용과 지연이 든다.
- **요약 경계에서 정보가 끊긴다**: 서브에이전트의 창 안에 남은 상세 로그·중간 추론은 메인 에이전트가 다시 들여다볼 수 없다. 요약이 놓친 세부가 다음 단계에 필요하면 되짚어갈 방법이 없다.
- **작은 작업에는 역효과**: 새 컨텍스트를 매번 새로 시작하는 비용(시스템 프롬프트 재구성, 왕복 지연)이 작업 자체보다 커지면 격리가 오히려 손해다.

## 주의사항

- 툴 허용 목록(`tools`)이나 차단 목록(`disallowedTools`)으로 서브에이전트가 쓸 수 있는 도구를 제한해, 격리를 비용 절감뿐 아니라 권한 통제에도 쓸 수 있다.
- 기본적으로 메인 대화 아래로 3단계까지만 서브에이전트를 중첩할 수 있고, 동시 실행 개수에도 기본 상한이 있다 — 무한히 쪼개지지 않는다.
- 여러 서브에이전트가 같은 파일을 동시에 고치면 충돌하므로, 격리된 작업 디렉터리(worktree)가 필요한 경우를 구분해야 한다.

## 핵심 정리

서브에이전트와 컨텍스트 격리는 [[오케스트레이터-워커]] 구조를 "컨텍스트를 어떻게 나누는가"의 관점에서 본 것이다. 탐색·반복 호출은 분리된 창에서 소모되고, 상위 컨텍스트에는 요약만 남는다. 다만 격리도 실제 API 호출과 지연을 수반하므로, 탐색이 충분히 길고 결과가 충분히 압축 가능할 때에만 이득이 남는다.
