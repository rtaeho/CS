앤트로픽이 Managed Agents 서비스 전체를 고객의 클라우드나 온프레미스 환경에서 직접 운영할 수 있는 셀프호스팅 옵션을 프라이빗 베타로 공개했다.
기준 시점: 2026-11-12

## 무슨 일인가

앤트로픽은 2026년 11월 12일 "Operate Claude Managed Agents inside your security perimeter" 글에서 셀프호스팅 Managed Agents가 프라이빗 베타로 제공된다고 밝혔다. 지금까지 Managed Agents는 앤트로픽이 인프라를 운영하는 호스팅 서비스였고, 그 전에는 코드가 실행되는 샌드박스만 고객 환경에 둘 수 있었다. 이번 발표는 그 범위를 하네스(에이전트 루프)·Managed Agents 서버와 데이터베이스·자격증명·세션 기록까지로 넓혀, 서비스 전체를 고객 환경 안에 둘 수 있게 했다고 설명했다. 모델 요청은 앤트로픽에 직접 보내거나 Amazon Bedrock·구글 Agent Platform·마이크로소프트 Foundry 같은 클라우드 제공자, 또는 고객이 직접 통제하는 게이트웨이로 보낼 수 있다고 밝혔다. 개발자는 호스팅 서비스와 동일한 핵심 API를 그대로 쓴다고 했다.

글은 호스팅형·부분 셀프호스팅형·완전 셀프호스팅형 모두에 적용되는 보안 원칙 네 가지를 들었다: (1) 하네스와 샌드박스를 분리해 툴이 필요할 때만 샌드박스를 띄운다, (2) 자격증명은 샌드박스 바깥의 프록시가 MCP 툴·API 호출에 주입해 샌드박스 안에 두지 않는다, (3) 환경별로 허용 호스트 목록을 두고 나머지 요청은 차단한다, (4) 툴 호출과 결과를 포함한 모든 단계를 OpenTelemetry로 내보내 기존 모니터링 도구와 연결한다. 조직이 앤트로픽과 제로 데이터 리텐션(ZDR) 정책을 맺고 있다면 Managed Agents의 Claude 요청에도 다른 Messages API 호출과 같은 방식으로 적용된다고 밝혔다.

## 왜 중요한가

에이전트가 빌드를 고치고 릴리스를 테스트하고 알림을 선별하는 등 사람 개입 없이 돌아가는 고위험 작업을 맡으면서, 회사 코드와 내부 시스템에 접근해야 하는 범위도 커졌다. 일부 조직은 코드가 실행되는 샌드박스만이 아니라 자격증명·세션 기록·제어 평면 자체를 자기 환경 안에 두길 원하는데, 지금까지는 그런 플랫폼을 직접 만들어야 했다고 글은 설명했다. 이번 공개로 그 선택지가 생겼다는 점에서 중요하다.

## 짚고 갈 개념

- 샌드박스 실행 — 에이전트의 셸·파일 툴이 돌아가는 격리 실행 환경. 이번 발표에서도 하네스와 분리된 채 툴이 필요할 때만 띄워진다
- 제로 데이터 리텐션(ZDR) — API 요청·응답을 서버에 저장하지 않는 정책. 조직이 이 정책을 맺었으면 Managed Agents 요청에도 같은 방식으로 적용된다고 밝혔다
- 모델 라우팅 — 이번 발표에서는 모델 요청을 앤트로픽·클라우드 제공자·고객 게이트웨이 중 어디로 보낼지 고르는 문제로 쓰였다

## 내 생각

하네스와 샌드박스를 분리하고 자격증명을 샌드박스 바깥 프록시에 두는 네 가지 보안 원칙은, 호스팅이든 셀프호스팅이든 같은 경계 설계를 유지하겠다는 선언으로 보인다. 다만 하네스까지 고객 환경에 두면 오케스트레이션·컨텍스트 관리·에러 복구 로직을 고객이 직접 최신 상태로 따라가야 할 가능성도 있어, 프라이빗 베타 단계에서 그 운영 부담이 실제로 어떻게 드러날지는 더 지켜봐야 할 것 같다.
