앤트로픽이 자사 엔지니어링 블로그에서 안전성 평가를 설계·실행·보고하는 방법을 단계별로 정리해 공개했다.
기준 시점: 2026-11-13

## 무슨 일인가

앤트로픽 엔지니어링 블로그는 2026년 11월 13일 "Building strong safety evaluations" 글에서, 안전성 평가가 모델을 배포할지, 어떤 안전장치와 함께 내보낼지, 다음 안전 학습을 어느 방향으로 할지를 정하는 근거로 쓰이기 때문에 평가 자체가 타당해야 한다고 전제했다. 좋은 평가는 만들기 어렵고, 심리학 분야가 재현성 위기를 겪으며 얻은 교훈(사전 등록, 측정 개선, 엄밀한 통계)을 안전성 평가에도 적용해야 한다고 밝혔다.

글은 평가를 설계(Design)·실행(Run)·보고(Report) 단계로 나눠 설명했다. 설계 단계에서는 관찰 연구만으로는 점수 차이의 원인을 알 수 없어 인과 주장을 하려면 변수를 하나씩 바꾸는 설계가 필요하다고 짚었고, 실제로 측정하려는 것을 측정하는 구성 타당도를 강조했다. 예로 거절률은 자살·자해 상담 같은 상황에서는 안전성을 잘못 나타낼 수 있어, 도메인별 루브릭으로 "적절한 응답률"을 따로 측정하고 유해 요청에 대한 순응과 무해한 요청에 대한 과잉 거절을 함께 봐야 한다고 설명했다. 실행 단계에서는 학습 데이터 오염과 모델의 채점 허점 악용(reward hacking)을 막아야 하고, 채점기(grader)는 사람 전문가끼리의 일치도 수준으로 사람 라벨과 맞아야 한다고 밝혔다. 분석 계획과 비교 대상을 결과를 보기 전에 미리 적어두는 사전 등록도 권장하며, 다중 턴 평가는 최소 100개, 단일 턴 평가는 최소 1,000개 항목을 기준으로 제시했다. 보고 단계에서는 신뢰구간을 함께 제시하고 실행 설정을 문서화해 재현 가능하게 하며, 설정이 다른 점수끼리는 비교하지 않아야 한다고 했다.

다중 턴 평가는 대화 전체를 채점하며 "한 번의 잘못된 턴이 대화 전체를 실패로 만든다"고 설명했다. 수치 예시로는 최근 모델들의 API 단일 턴 무해 응답률이 94~98%이고, 한 시스템 카드에서 API 적절 응답률은 60%였지만 새 시스템 프롬프트를 적용한 claude.ai에서는 94%로 나타나 설정 차이가 최대 34%포인트까지 벌어질 수 있다고 밝혔다. 로맨스 사기 평가에서 Opus 5(98%)와 Opus 5.5(94%)의 차이는 통계적으로 유의하지 않았다고도 덧붙였다.

## 왜 중요한가

이 글은 새 모델이나 기능을 발표하는 소식이 아니라, 안전성 수치 자체를 어떻게 믿을지를 다루는 방법론 글이다. 지금까지의 소식들이 "어떤 안전장치를 넣었다"는 결과를 보여줬다면, 이 글은 그 결과를 뒷받침하는 평가가 얼마나 엄밀하게 설계됐는지 스스로 점검하는 기준을 공개한 셈이다. 에이전트를 직접 평가해야 하는 입장에서는 거절률 같은 손쉬운 지표가 실제 목적과 다를 수 있다는 점, 채점기가 사람 판단과 얼마나 일치하는지 검증하지 않으면 점수 자체가 의미를 잃는다는 점을 구체적인 수치(설정 차이 최대 34%포인트)로 보여준다는 점에서 참고할 만하다.

## 짚고 갈 개념

- 에이전트 평가 — 최종 답만이 아니라 여러 턴에 걸친 행동 전체를 평가해야 하는 이유를 다루는 개념. 이 글의 "한 번의 잘못된 턴이 전체를 실패로 만든다"는 다중 턴 평가 설명과 바로 이어진다
- LLM-as-judge — 모델로 모델의 출력을 채점할 때의 편향과 완화책을 다루는 개념. 이 글의 채점기 보정(사람 라벨과의 일치도 검증) 내용과 맞닿아 있다

## 내 생각

구성 타당도 지적(거절률이 안전성과 같지 않다는 점)은 평가 지표를 고를 때 흔히 걸리는 함정이라 에이전트 평가 전반에도 그대로 옮겨볼 만하다고 보인다. 다만 수치 예시들이 전부 앤트로픽 내부 시스템 카드에서 나온 것이라, 다른 회사나 공개 평가 스위트에도 같은 기준(다중 턴 최소 100개, 단일 턴 최소 1,000개)이 통용되는지는 이 글만으로는 판단하기 어려워 보인다.
