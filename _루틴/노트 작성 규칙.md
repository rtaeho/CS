# 자동 정리 루틴 규칙

클라우드 루틴(`CS 노트 자동 정리`)이 매 실행 때 읽는 규칙 본문이다.
**루틴 프롬프트에는 이 파일을 읽으라는 지시만 들어 있고, 실제 규칙은 전부 여기 있다.**

그렇게 나눈 이유: 루틴 프롬프트를 API로 갱신할 때 긴 한글 본문을 다시 보내야 하는데,
그 과정에서 한글이 깨져 없는 파일 경로가 박힌 적이 여러 번 있다.
규칙을 레포 파일로 두면 수정이 평범한 커밋이 되고 diff로 확인할 수 있다.

`status: draft`라 이 파일 자체는 블로그에 올라가지 않는다.

---


## 1. 사전 검증

- master 최신 상태 동기화: `git checkout master 2>/dev/null; git pull --ff-only origin master`
- 작업 트리가 깨끗하지 않으면 기존 변경을 건드리지 말고 중단한다.

## 2. 오늘 할 일

한 번 실행에 **두 부**를 한다. 서로 독립적이다. 한쪽이 이미 처리됐거나 실패해도 다른 쪽은 그대로 진행한다.

- **1부 — AI 소식 1편** (읽는 글). 조사해서 쓰고, 거기서 나온 개념을 개념 체크리스트에 적립한다.
- **2부 — 개념 노트** (설명하는 글). 체크리스트의 다음 항목을 정리한다.

두 부의 중복 판정은 서로 다르고 각 절에 적혀 있다. **둘 다 할 일이 없으면 커밋 없이 종료한다.** 커밋은 두 부의 변경을 합쳐 **하나**로 묶는다.

## 3. 1부 — AI 소식

### 3-1. 오늘 몫이 남았는지 판정

`AI 소식/_다룬 주제.md`의 `## 기록` 아래 줄들을 본다. 오늘 날짜(`date +%Y-%m-%d`)로 시작하는 줄이 이미 있으면 1부는 건너뛰고 2부로 간다.

### 3-2. 조사

- WebSearch로 최근 소식을 찾는다. **검색어를 매번 바꾼다.** 예: AI 에이전트 프로토콜, 모델 릴리스, 에이전트 평가, 툴 사용, 컨텍스트, RAG, 추론 모델, AI 규제, 에이전트 보안.
- 후보 중 **개념을 끌어낼 수 있는 것**을 고른다. 투자 유치·인사 이동·주가처럼 기술 개념이 없는 소식은 고르지 않는다.
- `_다룬 주제.md`에 이미 있는 주제는 다시 쓰지 않는다. 같은 흐름의 후속 소식이라면 새로 짚을 각도가 분명할 때만 쓴다.
- 고른 소식은 **WebFetch로 원문을 직접 받아 읽는다. 검색 결과 스니펫만 보고 쓰지 않는다.** 원문을 못 받으면 다른 후보로 바꾼다. 후보를 셋까지 시도해도 원문을 하나도 못 받으면 1부를 건너뛰고 그 사실을 보고한다.
- 1차 출처(공식 블로그·사양 문서·논문·릴리스 노트)를 우선한다. 기사만 있으면 기사라도 쓰되 1차 출처를 한 번 더 찾아본다.

### 3-3. 노트 작성

저장 위치는 `AI 소식/{제목}.md`. 제목에 날짜를 넣지 않는다 — 블로그가 커밋 날짜를 함께 띄운다.

frontmatter는 title(파일명과 동일) / tags / status: published. 태그 첫 개는 `AI소식`으로 고정하고 뒤에 주제 태그를 붙인다.

**이 폴더의 글은 설명하는 글이 아니라 읽는 글이다.** 다른 폴더처럼 정의를 나열하지 말고, 무슨 일이 있었고 그게 왜 중요하며 직접 만들 때 무엇이 달라지는지 순서로 쓴다. 분량은 다른 노트보다 짧아도 된다.

- 첫 줄: 무슨 일이 있었는지 한 문장. `# 제목`은 쓰지 않는다.
- 그 **바로 다음 줄**에 `기준 시점: YYYY-MM-DD` (소식은 날짜까지 적는다).
- 섹션은 `## 무슨 일인가` / `## 왜 중요한가` / `## 짚고 갈 개념` / `## 내 생각` 을 기본으로 쓴다. 쓸 내용이 없는 섹션은 비우지 말고 뺀다.
- `## 짚고 갈 개념`: 이 소식을 이해하는 데 필요한 개념을 1~3개, 한 줄씩. 레포에 노트가 이미 있으면 `[[노트명]]`으로 연결하고, **없으면 링크 없이 평범한 문구로 쓴다.**
- 맨 아래 `## 출처` 섹션에 **실제로 WebFetch로 읽은 URL만** 적는다. 읽지 않은 링크는 넣지 않는다.

**사실 규칙이 가장 중요하다.**

- 날짜·버전 번호·숫자·회사명·제품명은 **원문에 있는 것만** 쓴다. 기억이나 추측으로 채우지 않는다.
- 확실하지 않으면 단정하지 말고 "…로 알려져 있다", "…라고 밝혔다"처럼 출처를 드러내 쓴다.
- 해석과 전망은 **`## 내 생각` 안에만** 두고, 거기서는 "…로 보인다"처럼 추측임을 드러낸다. 사실 섹션에 섞지 않는다.

### 3-4. 개념 적립 (이 갈래의 핵심)

`## 짚고 갈 개념`에서 **레포에 노트가 없는 개념**을 미완료 항목으로 적립한다. 소식이 개념 노트의 소재를 공급하는 구조이고, 이 적립을 빼먹으면 고리가 끊긴다.

넣을 곳이 두 군데다. 개념의 성격으로 가른다.

1. **에이전트 쪽 개념이고 `AI/_진행체크리스트.md`의 기존 섹션에 맞으면** 그 섹션 맨 끝에 넣는다. 새 섹션은 만들지 않는다.
2. **맞는 섹션이 없으면 `AI 소식/_개념 대기열.md`의 `## 대기열` 맨 끝에 넣는다.** 저장·배포·네트워크·자료구조처럼 AI가 아닌 개념이 여기로 온다. 버리지 않는다.

- 형식은 각 파일의 기존 줄과 똑같이: `- [ ] 제목 — 범위` 뒤에 백틱으로 감싼 저장 경로.
- 대기열 항목의 저장 경로는 그 개념에 맞는 기존 카테고리 폴더로 정한다(`Infa/` `Network/` `자료구조/` `BE/` `DB/` `FE/` `OS/`). 폴더를 새로 만들지 않는다.
- 대기열 항목 끝에는 출처 소식으로 돌아가는 `← [[소식 노트 제목]]`을 붙인다.
- 이미 있는 항목과 같은 개념이면 추가하지 않는다. 추가한 항목은 `[ ]` 상태여야 한다.
- **두 곳을 합쳐 하루에 최대 3개까지만 추가한다.** 대기열의 미완료가 이미 10개를 넘으면 대기열에는 더 넣지 않는다(쌓아두기만 하는 목록이 되지 않게).

### 3-5. 기록

`AI 소식/_다룬 주제.md`의 `## 기록` 맨 아래에 한 줄을 추가한다: `- YYYY-MM-DD · {제목} — {한 줄 요지}` 뒤에 백틱으로 감싼 노트 경로.

## 4. 2부 — 개념 노트

### 4-1. 오늘 몫이 남았는지 판정

오늘 이미 돌았는지는 **체크리스트의 체크 전환으로 판정한다. 커밋 메시지로 판정하지 않는다** — 사람이 손으로 만든 `docs:` 커밋을 자기 커밋으로 오인하기 때문이다.

```
git log --since="$(date +%Y-%m-%d) 00:00:00" -p -- 매일메일/_진행체크리스트.md 알고리즘/_진행체크리스트.md AI/_진행체크리스트.md | grep -E '^\+- \[x\]' | head -1
```

출력이 있으면 2부는 건너뛴다. 비어 있으면 계속 진행한다.

### 4-2. 매일메일 업스트림 신규 질문을 먼저 반영한다

매일메일에 새 질문이 올라와도 체크리스트에 없으면 영원히 처리되지 않는다.

- 질문 목록 원문(제목과 ID가 같이 있다):
  - https://raw.githubusercontent.com/maeil-mail/maeil-mail-contents/main/backend/toc.md
  - https://raw.githubusercontent.com/maeil-mail/maeil-mail-contents/main/frontend/toc.md
  - 줄 형식: `- [질문 제목](contents/be-152.md)`
- toc에 있는 be-N / fe-N 중 `매일메일/_진행체크리스트.md`에 없는 ID를 추려, 해당 섹션(Backend 또는 Frontend) 맨 끝에 기존 줄과 같은 형식으로 추가한다.
- **이미 있는 항목의 체크 상태는 절대 건드리지 않는다. 추가만 한다.**
- toc 다운로드가 실패하면 이 단계만 건너뛰고 진행한다. 이 단계 실패로 전체를 중단하지는 않는다.

### 4-3. 갈래 선택

갈래가 셋이고 위에서부터 우선한다.

- `매일메일/_진행체크리스트.md`에 미완료 `[ ]`가 있으면 → **A 갈래(매일메일)**. Backend 첫 번째 1개 + Frontend 첫 번째 1개, 총 2개. 한쪽만 남았으면 1개.
- 매일메일이 비었고 `알고리즘/_진행체크리스트.md`에 미완료가 있으면 → **B 갈래(알고리즘)**. 첫 번째 `[ ]` 1개만.
- 둘 다 비었고 `AI/_진행체크리스트.md`에 미완료가 있으면 → **C 갈래(AI 개념)**. 첫 번째 `[ ]` 1개만.
- 셋 다 비었고 `AI 소식/_개념 대기열.md`에 미완료가 있으면 → **D 갈래(소식에서 나온 개념)**. 첫 번째 `[ ]` 1개만.
- 넷 다 미완료가 없으면 2부에서 노트를 만들지 않는다. 4-2에서 추가된 항목이 있으면 그 변경은 커밋에 포함한다.

### 4-4. A 갈래 — 매일메일

항목 끝의 be-N / fe-N ID로 원문을 받는다.

- Backend: https://raw.githubusercontent.com/maeil-mail/maeil-mail-contents/main/backend/contents/{be-id}.md
- Frontend: https://raw.githubusercontent.com/maeil-mail/maeil-mail-contents/main/frontend/contents/{fe-id}.md
- 다운로드가 실패하면 A 갈래를 건너뛰고 원인을 보고한다.

**기존 노트 확인 (새 파일 만들기 전 필수)**
일반 CS 노트 카테고리 폴더: `AI/` `BE/` `DB/` `FE/` `Infa/` `Network/` `OS/` `알고리즘/` `자료구조/`

- 같은/유사 개념 노트를 레포 전체에서 먼저 검색한다.
- 기존 노트가 충분하면 새로 만들지 말고 `[[기존 노트명]]`으로 연결만 한다.
- 원문에 독립 면접 질문이 될 만한 핵심 개념이 있는데 기존 노트가 없거나 빈약하면 일반 노트를 새로 만들거나 보완한다.

**일반 CS 노트 형식 (기존 노트의 실제 관례를 반드시 따를 것)**
frontmatter는 title(파일명과 동일) / tags / status: published 세 개.

- frontmatter 다음 첫 줄은 개념을 설명하는 한 문장.
- `# 제목` 사용 금지. 본문은 `##` 섹션으로 구성.
- 관련 개념은 본문 안에서 `[[주제명]]` 인라인 위키링크로 연결한다.
- **일반 노트에는 `관련 개념:` 이라는 별도 줄을 쓰지 않는다** (기존 노트 중 2개뿐인 예외 형식).
- 파일 맨 아래에는 해당 매일메일 노트로 가는 백링크 한 줄만 둔다: `→ [[질문 제목]]`
- 태그에 공백·쉼표가 들어간 단일 태그 금지. 코드 예시는 Backend는 Java, Frontend는 JS/TS.

**매일메일 노트 형식**
저장 위치: Backend는 `매일메일/BE/`, Frontend는 `매일메일/FE/`
파일명은 체크리스트의 질문 제목(마지막 마침표는 제거 가능). 제목에 큰따옴표가 있으면 파일명에서는 제거한다.
frontmatter는 title / tags([매일메일, Backend] 또는 [매일메일, Frontend]) / status: published.

- frontmatter 바로 아래에 `관련 개념: [[노트A]] · [[노트B]]` 줄을 둔다(이게 매일메일 노트의 표준).
- **원문의 섹션 구조·코드 예시·외부 링크를 그대로 보존한다.** 원문에 없는 자체 섹션을 새로 추가하지 않는다.
- **원문이 답을 비워두고 "스스로 답변을 하는 연습을 해보세요"라고 남긴 질문은 답을 채우지 말고 그대로 보존한다.**

### 4-5. B 갈래 — 알고리즘

저장 위치는 체크리스트 항목 끝에 적힌 경로를 그대로 따른다.

- 먼저 레포 전체에서 같은 알고리즘 노트가 이미 있는지 검색한다. 이미 충분한 노트가 있으면 새로 만들지 말고 체크리스트만 `[x]`로 바꾸고 그 사실을 보고한다.
- **이름이 확립된 정식 알고리즘만 정리한다. 특정 문제의 풀이 조합에 새 이름을 붙여 노트로 만들지 않는다.**
- 형식은 기존 `알고리즘/정렬/퀵 정렬.md`, `알고리즘/그래프/다익스트라.md`, `알고리즘/DP/LCS.md` 관례를 따른다. frontmatter는 title(파일명과 동일) / tags / status: published.
  - frontmatter 다음 첫 줄은 알고리즘을 설명하는 한 문장. `# 제목` 금지.
  - `## 동작 과정` — 작은 입력에 대한 단계별 추적을 코드블록 안에 ASCII로 그린다.
  - `## 구현` — Java 코드.
  - `## 복잡도` — 시간·공간 복잡도와 그 근거.
  - 필요하면 `## 주의사항`(흔한 실수, 적용 조건), `## 핵심 정리`를 덧붙인다.
- 관련 개념은 본문 안에서 `[[주제명]]` 인라인 위키링크로 연결한다. 특히 `자료구조/` 폴더의 기존 노트(`[[PriorityQueue]]` `[[Heap]]` `[[Queue]]` `[[HashMap]]` `[[트라이]]` 등)와 잇는다.

### 4-6. C 갈래 — AI 개념

저장 위치는 체크리스트 항목 끝에 적힌 경로를 그대로 따른다. 항목의 `—` 뒤에 그 노트에서 다룰 범위가 적혀 있으니 그 범위를 지킨다.

이 갈래의 목적은 **에이전트를 실제로 만들 때 쓰는 개념과 방법론**이다. 모델 내부(파라미터·학습법)로 빠지지 않는다.

형식은 다른 노트와 같되(frontmatter title/tags/status: published, `# 제목` 금지, `##` 섹션) 두 가지가 다르다.

- frontmatter 다음 설명 한 문장 **바로 아래 줄**에 `기준 시점: YYYY-MM` 을 적는다. 실행 시점의 연·월을 쓴다.
- 파일 맨 아래에 `## 참고` 섹션을 두고 출처 링크를 적는다. 사양·논문·공식 문서를 우선한다.

섹션 구성은 주제에 맞게 고른다. 알고리즘처럼 고정하지 않는다. 다음이 쓸 만하다.

- `## 왜 필요한가` — 이 개념이 없을 때 생기는 문제부터 쓴다.
- `## 구조` 또는 `## 동작 과정` — 흐름은 코드블록 안에 ASCII 다이어그램으로 그린다.
- `## 구현` — 필요할 때만. 언어는 Python 또는 TypeScript. 개념 노트에 억지로 코드를 넣지 않는다.
- `## 트레이드오프` — 비용·지연·복잡도 중 무엇을 내주는지.
- `## 주의사항` — 실제로 만들 때 밟는 함정.
- `## 핵심 정리`

**사실 확인이 가장 중요하다.** AI 쪽은 사양과 생태계가 빠르게 바뀐다.

- 확실하지 않은 최신 동향은 단정하지 말고 "…로 알려져 있다"로 쓰거나 아예 쓰지 않는다.
- 버전 번호, 날짜, 기업 이름을 지어내지 않는다. 체크리스트 항목에 이미 적혀 있는 사실은 그대로 쓴다.
- WebFetch가 막히면 받아오지 못했다고 보고하고, 확인된 범위 안에서만 쓴다. 못 받았다고 중단하지는 않는다.

### 4-7. D 갈래 — 소식에서 나온 개념

`AI 소식/_개념 대기열.md`에 쌓인 항목이다. 소식 글에서 뽑혔지만 AI 에이전트 주제는 아닌 일반 CS 개념이다.

- 저장 위치는 항목 끝에 적힌 경로를 그대로 따른다. `—` 뒤가 다룰 범위다.
- 형식은 **그 폴더의 일반 CS 노트 관례**를 따른다(4-4의 일반 CS 노트 형식과 같다). frontmatter는 title(파일명과 동일) / tags / status: published, 첫 줄은 개념을 설명하는 한 문장, `# 제목` 금지, `##` 섹션.
- **`기준 시점` 줄은 쓰지 않는다.** 시의성 있는 소식이 아니라 개념 노트다. `## 참고`도 필수가 아니다.
- 항목 끝의 `← [[소식 노트 제목]]`이 출처다. 노트 맨 아래에 그 소식으로 가는 백링크 한 줄을 둔다: `→ [[소식 노트 제목]]`
- **고리를 닫는다.** 그 소식 노트의 `## 짚고 갈 개념`에서 이 개념이 링크 없는 평범한 문구로 적혀 있을 것이다. 이제 노트가 생겼으니 그 자리에 `[[개념 이름]]` 위키링크를 걸어준다.
- 대기열 항목을 `[x]`로 바꾸고 상단 통계를 다시 센다.

## 5. 위키링크 공통 규칙

기존 노트가 이번 주제를 이름으로 언급하고 있으면(grep으로 확인) 그 자리에 위키링크를 걸어 연결한다. 단 아래 네 가지를 지킨다.

- **영문 약어는 단어 경계를 확인한다.** `LIS`를 그냥 치환하면 `PUBLISHED`가 `PUB[[LIS]]HED`로 깨진다. `RAG`, `MCP` 같은 짧은 약어도 같다.
- **코드블록 속은 건드리지 않는다.**
- **더 긴 다른 개념을 가로채지 않는다.** `이진 탐색`을 치환하면 `이진 탐색 트리(BST)`가 `[[이진 탐색]] 트리`가 된다. BST는 다른 개념이다.
- 본문 의미를 바꾸지 않는 최소 수정만 하고, `progress.md`는 건드리지 않는다.

상위 주제 노트가 있으면 파일 맨 아래에 백링크 한 줄을 둔다(예: 정렬 계열은 `→ [[정렬]]`, DP 계열은 `→ [[동적 계획법]]`). 없으면 생략한다.
**아직 없는 노트로 가는 위키링크는 걸지 않는다.** 연결하고 싶으면 링크 없는 평범한 문구로 쓴다.

**노트 제목은 레포 전체에서 유일해야 한다.** 위키링크는 폴더가 아니라 제목으로 대상을 찾으므로, 같은 제목이 두 폴더에 있으면 `[[제목]]`이 어디로 가는지 정해지지 않는다. 노트를 만들기 전에 반드시 확인한다.

```
find . -name "*.md" -not -path "./.git/*" | sed 's|.*/||' | LC_ALL=C sort | LC_ALL=C uniq -d
```

(`LC_ALL=C`를 빼면 macOS에서 한글 파일명이 거짓으로 중복 판정된다.)

체크리스트 항목의 이름이 기존 노트와 겹치면 **항목 이름과 경로를 바꿔서** 만들고, 체크리스트의 그 줄도 같이 고친 뒤 왜 바꿨는지 한 구절 남긴다. 2026-10-25에 `리플렉션`이 `BE/리플렉션.md`(Java 런타임 기능)와 겹쳐 `에이전트 리플렉션`으로 바꾼 사례가 있다. 겹친 개념끼리는 본문에서 "이름만 같고 다른 개념"이라고 한 줄로 갈라주면 읽는 사람이 헷갈리지 않는다.

## 6. 체크리스트 갱신

- 2부에서 처리한 항목을 `[ ]` → `[x]`로 바꾼다. 건드린 체크리스트만 수정한다. `AI 소식/_개념 대기열.md`도 같은 규칙을 따르는 체크리스트다.
- 1부 3-4에서 추가한 항목과 2부 4-2에서 추가한 항목까지 포함해 실제 체크박스 개수를 다시 세어 상단 전체 통계와 각 섹션 헤더 숫자를 모두 갱신한다.
- 상단 통계와 실제 개수가 일치하는지 검증한다.
- 1부와 2부가 **같은 `AI/_진행체크리스트.md`를 건드릴 수 있다.** 1부는 항목을 추가하고 2부는 항목을 체크하므로, 둘을 모두 반영한 뒤 마지막에 한 번만 통계를 다시 센다.

## 7. 최종 검증 (하나라도 실패하면 커밋·푸시 금지, 원인 보고)

- 생성·수정한 모든 노트에 유효한 YAML frontmatter가 있고 title이 파일명과 같은가
- 노트가 frontmatter 다음 설명 문장으로 시작하고 `# 제목`이 없는가
- 중복된 노트를 만들지 않았는가
- **새 노트 제목이 레포의 다른 노트 제목과 겹치지 않는가**(위 `uniq -d` 명령으로 확인, `_진행체크리스트.md` 외에 중복이 나오면 안 된다)
- **모든 위키링크 대상 파일이 실제로 있는가(끊긴 링크 0개)**
- **기존 노트에 링크를 추가한 diff를 직접 확인해 단어 중간이 깨지지 않았는가**
- 체크리스트 통계가 실제 체크박스 개수와 일치하는가
- 2부에서 오늘 선택한 항목만 완료 처리됐는가 (새로 추가한 항목은 `[ ]` 상태여야 한다)
- 1부를 했다면 `기준 시점` 줄과 `## 출처` 섹션이 있는가, 출처에 **실제로 읽은 URL만** 있는가, 지어낸 날짜·버전·숫자가 없는가
- 1부를 했다면 `AI 소식/_다룬 주제.md`에 오늘 줄이 추가됐는가
- **1부를 했다면 `## 짚고 갈 개념`의 각 개념이 (a) 이미 노트가 있거나 (b) AI 체크리스트에 적립됐거나 (c) 대기열에 적립됐는가. 셋 중 어디에도 없는 개념이 남아 있으면 적립을 빠뜨린 것이다**
- D 갈래라면 출처 소식 노트의 해당 개념 줄에 위키링크를 되걸었는가, `기준 시점` 줄을 넣지 않았는가
- C 갈래라면 `기준 시점` 줄과 `## 참고` 섹션이 있는가, 지어낸 버전·날짜가 없는가
- B 갈래라면 Java 코드가 컴파일 가능한 형태인가(변수 선언·괄호·타입 확인)

## 8. 커밋과 푸시

검증 성공 시에만 변경 파일 전체를 **하나의 커밋**으로 묶는다.

커밋 author를 반드시 고정한다(안 하면 GitHub 잔디에 반영되지 않음):

```
git -c user.name="rtaeho" -c user.email="ryou0920@naver.com" commit -m "..."
```

커밋 메시지

- 1부와 2부를 모두 했으면: `docs: AI 소식 {소식 주제}와 {개념 이름} 정리`
- 1부만 했으면: `docs: AI 소식 {소식 주제} 정리`
- 2부만 했고 A 갈래면: `docs: 매일메일 {Backend 핵심 개념}·{Frontend 핵심 개념} 정리`
- 2부만 했고 B·C·D 갈래면: `docs: {주제 이름} 정리`
- 체크리스트 항목 추가만 한 경우: `docs: 체크리스트 신규 항목 N건 추가`

규칙

- 실제 실행 날짜·시간으로 커밋한다. 과거 날짜로 위조 금지.
- Co-authored-by 태그 절대 추가 금지.
- `origin master`로 푸시한다. push 전 원격 변경이 생겼으면 다시 동기화하고 충돌을 확인한다.
- force push 절대 금지.
